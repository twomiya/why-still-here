# 《你为什么还没辞职？》静态网页原型

## 打开与部署

- 本地体验：直接用浏览器打开 `index.html`。
- 线上地址：https://twomiya.github.io/why-still-here/ （GitHub Pages，从 `main` 根目录发布）。
- 页面没有后端依赖，也不需要数据库或 API 密钥。改动推送至 `main` 后，仍需等待 Pages 更新并验证公开页面。
- 手机与桌面都应实际答完一遍，检查文字换行、选项点击区域和结果页是否溢出。

## 隐私边界

- 答案只在页面运行期间留在浏览器内存；刷新即清空。页面代码没有提交答题数据的网络请求，也没有本地存储逻辑。
- 结果页显示少量答题依据；分享卡只使用概括性结果文案，不包含收入、家庭等原始回答，也不提供反馈上传。
- **托管平台仍可能记录页面访问日志**；若要正式发布，应检查托管方的日志、隐私设置、域名和任何额外加入的统计脚本。不要在未核对部署环境前宣称整个站点“零数据收集”。
- 题目涉及工作、经济及家庭处境；避免添加未经用户明确同意的自动分析或埋点。

## 原型的能力与限制

- 功能：12 题逐题作答、答题时返回修改、六类结果（观察、解释与自问问题）、对应依据列表、可复制／下载图片的分享卡、重新测试。
- 判定先看明确的现实限制；其他倾向至少需要不同题目的线索相互支持。真实经历与假设情境会在结果中区分；证据不足或互相冲突时显示“不足以确定主因”。
- 这套规则是待验证的产品假设，没有经过心理测量验证。这是帮助自我梳理的内容，不是心理诊断、职业建议或“应该辞职”的判断。
- 测试脚本 `test_prototype.py` 留在源目录，需本地 Chrome 和 Python Playwright；默认直接读取本地 `index.html`，也可用 `QUIZ_URL` 测试线上页面。交付包包含网页及两份说明文档。

## 发布前检查

1. 在手机和桌面浏览器上，从首页答到结果；在答题中返回修改，并在结果页重新开始。
2. 选几组边界答案：现实阻力明显；没有唯一倾向；关键现实题选“不想回答”。确认不会硬贴标签。
3. 检查窄屏是否出现横向滚动，选项是否容易点中，依据列表与分享卡是否清晰且不含敏感回答。
4. 从公开 HTTPS 地址检查线上文件确实是最新版本；再用 `PILOT.md` 的方案组织真实试答。
